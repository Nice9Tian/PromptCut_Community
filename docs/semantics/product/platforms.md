# 平台

展开 `../architecture.md` 的「默认位置」和扩展点，以及 `../product-purpose.md` 的范围。从属于 `architecture.md`，与它冲突时以它为准。本册写产品功能（二级）；怎么做到见 `../mechanism/platforms.md`。

## 面向的平台

| 平台 | 运行形态 | 一期 |
|---|---|---|
| 桌面应用 | 带预渲染进程，可在本机运行文档服务和素材服务 | 做 |
| 桌面浏览器 | 在线浏览器 | 做 |
| iPad 浏览器 | 在线浏览器 | 做 |
| iPad 应用 | 在线浏览器套壳，没有预渲染进程 | 不做 |
| 手机浏览器 | 在线浏览器 | 做 |
| 手机应用 | 在线浏览器套壳 | 不做 |

- 电脑、iPad、手机的浏览器都是「在线浏览器」，同一个页面、同一套规则，不分档（2026-10-07 用户定；原先 2026-09-27 定的「低内存档」撤销，「普通档」一词随之不用）。个别功能按身份或性能回退，规则见下文「在线浏览器」。
  - 代码里的低内存档、设备设置里的「显示档」、进入低内存档的提示、运行中自动降档，都待按「在线浏览器」一节改掉；机制文档里相应的做法尚未改写的，以「在线浏览器」一节为准。
- Agent 端（Agent 服务与预渲染进程的 Agent 模式、Full 模式）面向 Windows、Linux、Ubuntu。云端 Agent 服务跑在 Linux 云节点上，不带编辑界面。

## 渲染节点

预渲染由认领任务的渲染节点完成（队列规则见 `document-service.md` 的「渲染任务队列」）。

| 节点 | 是什么 | 能认领什么 |
|---|---|---|
| 本机 PC | 桌面应用的预渲染进程，单项目模式 | 全部：轨道流的稀疏版和满密度版，内置卡、用户卡、素材效果卡的都算 |
| 独立渲染主机 | 局域网或远程主机上的预渲染进程，不带编辑界面，多项目模式 | 全部；可以同时为多个项目、多个用户取活，不被哪个项目占着 |
| 托管方的渲染服务 | 云节点上托管方自带的独立渲染主机：主要为同机的云端 Agent 即时出图（不经队列），其次产流；0.7.19 起多项目模式，0.7.18 的暂行办法见 `rendering.md`「即时渲染与预渲染进程」 | 放在这台节点上、创建者没关掉它的项目里，「生成轨道流」打开的那些项目的产流任务 |
| 纯浏览器 | 身份为电脑的在线浏览器的后台舞台 | 只认领当前登录用户自己产生的单卡轨道流任务（稀疏版和满密度版）；内置卡片、用户卡都可以，前提是这张卡在本页能运行；素材效果卡的任务不认领（整屏画面太大）〔裁:主会话 2026-10-06,待用户合入前审〕 |

- 手机、平板也为本页产稀疏版（2026-10-14 用户定）：手机、平板打开项目时也给当前页要播放的重卡产稀疏版（开工前询问浏览器能否编 H.264，答不能或连错 3 次则不产；只产稀疏版，不产满密度版；满密度版由电脑类设备补）；不替别的项目和成员干活。
- 节点只在闲时认领：本机 PC 和纯浏览器在用户播放、拖动时不认领新任务，手里在做的那一批做完为止；播放、拖动时在线页面的节点每隔一段时间向队列报「还在」，它锁着的卡不因此被别的环境接手，拖动时自己浏览器在产的流同样不被别的机器抢走（2026-10-14 用户定）。
- 强的设备可以抢弱的设备领着的产流任务（2026-10-14 用户定）：优先级为桌面版 > 托管方的渲染服务（「生成轨道流」打开时）> 浏览器；桌面版做完自己的活可以抢电脑浏览器领着的产流任务，弱设备推上去的分段保留，被接走后停下。电脑浏览器和手机、平板同属浏览器级，彼此不抢。
- 加入共享项目的桌面应用自动成为这个项目的渲染节点，可以认领本项目任何成员发布的任务。
- **只能出网的节点**：没有入站连接、出网只能经代理走 443 端口 HTTPS 的机器，例如云端容器。
  - 它永远是成员，不能当主机。加入放本机的项目只能走中继路径（见 `document-service.md` 的「部署组合」）。
  - 它可以新建放云端的多用户协作项目，这不使它成为主机。
  - 当渲染节点时和别的节点一样按能力认领，例如没有本机转码就不认领要转码的任务。
- 纯浏览器节点绝不替别的用户干活，同一共享项目的其他成员也不行：既不让别人的项目内容进用户的浏览器，也不让用户的设备算力被别人占用。这条边界由文档服务按登录凭证把关（见 `document-service.md` 的「渲染任务队列」）。

## 桌面应用

- 桌面应用自带运行所需的全部组件：Node、Chrome、ffmpeg、内置 Python。用户不需要自己安装它们。
- 桌面应用所在的是**桌面运行环境**：它可以连本地的服务，也可以连云端或别人本机的服务，两者可以混合，见 `document-service.md` 的「部署组合」。
- 桌面应用可以在本机运行本地文档服务和本地素材服务；它们也可以为同一局域网里没有渲染能力的设备服务。项目勾上「多用户协作」并放本机时，本机的本地文档服务和本地素材服务就是这个项目的主机，成员按「连接路径」连上来（见 `document-service.md` 的「部署组合」）。
- **局域网里的第二块屏**（2026-10-26 用户定）：桌面应用打开一个项目之后，同一局域网里的手机、平板用浏览器打开桌面那台机器给出的地址，就进入**同一个本机项目**，内容以本机文档服务为准、两边实时同步。这条路**不要账号、不经云端、不是多用户协作项目**：它是同一个项目的第二个页面，用的就是桌面那台机器上已经在跑的本地文档服务和本地素材服务，所以也不属于「在线浏览器」那一档。手机上是手机版界面（见「在线浏览器」的「身份」）。桌面应用提供入口把地址给出来（含二维码，手机扫一下就进）。桌面应用**缺省只绑回环地址**，手机连不上；换绑要重起编辑器，所以这一版的入口在没绑局域网时只说清怎么起，「点一下就开门」另立一步（做法与限制见 `../mechanism/platforms.md`「局域网里的第二块屏」）。没有账号也就没有成员，手机上不显示成员。
- 内置 Python 只用于感知类工具（语音转写、镜头识别、运动追踪、主体检测、素材收集），不用于卡片。
- **更新补丁换不掉外壳，所以要新外壳的功能在老外壳上只给一句说明、不报错**（用户 2026-10-17 定，2026-10-22 实现）：更新补丁只换 Node 那一半的代码，外壳（Rust 壳、Chrome、ffmpeg、内置 Python）要装完整安装包才换。于是**要外壳支持的功能，在打了补丁但外壳还旧的机器上用不了**；这时界面给一句「这个功能要装完整安装包」的说明，并说明本地项目不受影响，而不是抛一个用户看不懂的错。现在属于这一类的是账号与云端项目那几个入口（开始页的云端项目、项目设置与协作房间里的「搬到云端」），它们要 0.2.8 外壳才有的桥。补丁清单声明的最低外壳不为此抬高。怎么认出外壳太老见 `../mechanism/platforms.md`。
- **预渲染缓存**〔裁：2026-09-29 PC 主会话按用户定的「帧库设上限、按项目最近使用淘汰、给清理缓存入口」写〕：桌面应用把预渲染结果缓存在本机（帧库）。缓存有容量上限，用户可以改；超出时按项目最近使用的先后，先清掉最久没用的项目的预渲染结果，正在打开的项目不清。清掉的结果需要时重新预渲染；共享项目的结果仍在素材服务里，可以取回。
- 用户可以随时「清理缓存」：清掉正在打开的项目以外的全部预渲染结果。
- **导出产物**：每次导出一份，留成片与只含卡片的透明层，逐帧图片等中间文件导出完成后自动删除〔裁：同上〕；取消或失败的导出留下的文件同样列出。用户可以查看历次导出的所属项目、时间与大小，删除整份，或只删中间文件。
- 项目放云端时，桌面应用的 AI 栏可以选「云端」，由托管方的云端 Agent 服务执行；缺省仍是本机 Agent。选「云端」的对话在云节点上运行，桌面应用退出（含后台运行一并退出）后继续，重新打开项目能找回。
- 关闭编辑界面后转入后台运行，见 `../user-workflow.md` 的「后台运行」。
- **舞台闸门限制**（2026-10-14 用户定）：桌面端舞台里运行的卡片代码（含别的成员同步来的）不许调本机预渲染进程和编辑器进程的接口；按哈希读素材只放行当前项目自己的素材（素材不能跨项目读取）。

## 在线浏览器

- **名词**（2026-10-07 用户定）：用浏览器打开页面来用本产品，统一叫「在线浏览器」。电脑、iPad、手机的浏览器都是它，同一个页面、同一套规则。不按设备种类预先分档，不给用户切换档位的设置。每台设备能做到哪一步，由下面三道**闸门**判出来。正式进入编辑界面后，用气泡告诉用户这台设备现在处在哪一档。四档的名字与气泡文字（2026-10-08 用户定）：顶配模式（两个舞台各一套渲染器）：「这台设备运行在顶配模式」；标准模式（两个舞台共用渲染器）：「这台设备运行在标准模式」；精简模式（只有一个舞台）：「这台设备运行在精简模式：复杂的效果交给云端渲染」；低配模式（最低一档）：「这台设备运行在低配模式：播放时只显示已渲染好的画面」。四档都提示。气泡出现在预览窗口上方，几秒后自动消失。
- **身份**：分「电脑」和「手机」。电脑与手机按浏览器的声明判；iPad 的声明分不出来，看舞台闸门：撑得住双舞台的算电脑，撑不住的算手机（2026-10-07 用户定，替换同日早些时候的「以第一代 iPad Pro 为界」）。身份决定两件事：电脑当渲染节点，手机不当（见上文「渲染节点」）；身份为手机的用手机版界面，其余用桌面界面（2026-10-21 用户定）。界面跟身份走，不给用户切换开关，也不看文档服务在哪：手机在局域网里打开桌面那台机器上的本机项目时同样是手机版界面（见「桌面应用」的「局域网里的第二块屏」）。
- **三道闸门**（2026-10-07 用户定；替换同日早些时候的「启动时跑一个小测试」与「查设备表」）。先舞台，再素材，再即时渲染；做法见 `../mechanism/platforms.md` 的「在线浏览器」。
  - **舞台闸门**。所有舞台一律跨源隔离，不再退回「同源单舞台」（2026-10-14 用户定）。三级，从低到高：一个舞台；两个舞台共用一套 canvas 渲染器；两个舞台各用一套。每次刚打开页面时从低往高试，哪一级把页面撑崩了，重新载入后就停在它的下一级，这次使用期间不再往上试。只在刚打开页面时试。崩一次就算，不等第二次。崩过之后有一段**护栏**时间：护栏内重新打开直接停在上次到达的那一级，不往上试；过了护栏再从头试。护栏随崩的次数加长（数字见 `../mechanism/platforms.md`），所以偶然崩一次只受限一小会儿，老是崩的设备越试越少，不会每次打开都崩一回，也不会永远受限。8 GB 的门槛只管安卓上的 Chrome 系浏览器（那里舞台崩了整页跟着崩，又不会自动重新载入）：报到 8 GB 内存才往上试，不到的直接停在一个舞台，不试。电脑上的 Chrome 系直接试（舞台崩了页面还在）；Safari 直接试（崩了会自动重新载入）。（2026-10-07 用户定）
  - **素材闸门**。两个子闸门：
    - 解码：打开时测出这台设备解得动多大的素材；超过上限的素材只用小尺寸，没超过的照常。解码上限打开时测一次，这次使用期间不变；之后导入的素材拿它和这个上限比，不重新测（2026-10-08 用户确认：「不用重新测，因为已经测得了最大支持的极限素材大小」；同日别的会话写的「随项目素材变化更新相关测量」作废）。
    - 网速：不单独测，看素材实际下载的快慢，使用中随时调整。它只决定要不要先拉小尺寸：够快就只拉原尺寸；低于界线就先拉小尺寸显示，再拉原尺寸替换。
    - 载入原尺寸把页面撑崩了的，重新载入后记得，不再照原样载入。
  - **即时渲染闸门**。就是轻重判定（见下文）：开始时逐张卡实测，跑得动的即时渲染，跑不动的当重卡。它依赖舞台闸门的结果（只有一个舞台时借可见舞台来测），之后随项目变化更新相关测量，不是开始时测一次。测某张卡把页面撑崩了的，重新载入后这张卡直接当重卡（2026-10-08 用户明确测量时机）。
- **最低一档**（2026-10-07 用户定）：连最简单的一张基准卡都跑不动，或连一个舞台都撑不住的设备，**播放时**不做任何即时渲染：画面全部用预渲染结果，没有预渲染结果的层显示占位符并发布任务，由渲染节点渲。**停下以后**先显示占位（有预渲染结果的层照常显示它），再尽量把当前这一帧渲出来，渲好一层替换一层，不设时限。素材用小尺寸。
- 预渲染结果只有轨道流一档。性能不足时只贴它的稀疏版，同时活着的解码器给得少；这一项归哪道闸门管，做的时候定。
- 页面本地的缓存上限按实测到的环境分配，不按身份或档位定固定数。
- 本机没有进程，文档服务和素材服务都在别处。请求不到预渲染进程，没有本机转码能力。轨道流能播放；身份为电脑的页面还能用浏览器自带的编码器生成单卡的轨道流；手机、平板在确认 H.264 编码支持后也给当前页面要播放的重卡产稀疏版轨道流（2026-10-14 用户定）。支持在浏览器里导入本地素材：页面上传，浏览器里转视频小尺寸先传，再传原尺寸（2026-10-14 用户定）。
- **能新建放云端的项目**（用户 2026-10-07 改定；原先是“只加入，不新建”）：开始页按钮写“新建云端项目”和“加入别人的项目”。未登录时除了“需要登录网站账号”，另给一个“以游客身份进入”（2026-10-23 用户定，游客能做什么见 `document-service.md`“游客”）；一律是放云端的多用户协作项目，创建者为该账号或该游客，归属由云端文档服务记录。项目内容、素材、预渲染结果在相应云端服务。每人可建数量目前不限，新建入口留好限制位置。桌面 `.proc` 打开仍只在桌面版；浏览器不提供本地草稿列表，但暂时离线的未提交改动必须持久保留，不能当可丢弃缓存（2026-10-08 离线行为，见 `document-service.md` 和 `../workflow/project.md`）。
- **入口**：服务器直接提供编辑器页面，地址是服务器地址加固定后缀（如 `/editor`），打开即是编辑器，不需要安装；页面连同一台服务器上的文档服务和素材服务。地址里不带软件版本，换版本不改地址（2026-10-23 用户定）。
  - **项目直达地址**（2026-10-23 用户定）：每个云端项目有一个直达地址（如 `/editor/p/<项目号>`）。进了项目，地址栏就换成它，刷新后还在这个项目里；打开它时已登录、又是成员就直接进项目；没登录先登录，登录后接着进；进不去就留在开始页：还不是成员的，链接已填好，提示点「加入并打开项目」加入（加入由用户自己点，不自动加）；要二级密码的照常弹出输入框；别的原因照常说明。
  - **分享链接**（2026-10-23 用户定）：分享出去的项目链接也不带软件版本（如 `/editor/s/<项目号>/<链接令牌>`），打开后和原来一样在开始页填好链接，登录后点加入；进了项目，地址栏换成直达地址，链接令牌不留在地址栏里。原来 `?project=…&token=…` 形式的链接照常能用。
- **不画应用标题栏**（2026-10-22 用户定，原话「浏览器版不需要『显示顶部菜单栏』和『放大缩小关闭』三个无用的按钮」「桌面版要有」）：浏览器里页面顶上不画桌面版那条标题栏——既没有「文件 / 编辑 / 视图 / 帮助」菜单行，也没有最小化、最大化、关闭三个按钮（它们是桌面窗口的，在浏览器里按了没反应）。菜单里在线还用得上的项都在编辑器顶栏上：导出视频、首页、撤销、重做、皮肤…是顶栏原有的按钮，「快捷键」「关于 PromptCut」在顶栏的「⋯」菜单里。桌面应用照旧有标题栏。这一条取代 `../../plan/c10-contract.md` 第 10 节 2026-09-28 那条「在线标题栏菜单同顶栏、桌面项置灰」的〔裁〕。
- 打开 `/editor` 第一页是开始页，新建与加入都在这里，加入的表单与桌面版相同（见 `../workflow/project.md` 的「多用户协作」）；打开项目直达地址的，按上文直接进项目（2026-10-23 用户定，原写「页面打开后的第一页是开始页」）。
