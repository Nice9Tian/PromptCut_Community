# 用户工作流程

本文是指导层：用户有哪几种工作方式、主线分几步、人和 Agent 协作时守哪些规则。每一步的功能清单在 `workflow/` 分册。分册从属于本文，与本文冲突时以本文为准。

## 工作方式

用户在同一个项目上可随时切换三种方式，切换不丢状态。三种方式都是人与 Agent 协作，区别在 Agent 从哪里接入、编辑界面是否打开。

| 方式 | 界面 | 谁在动手 |
|---|---|---|
| **氛围式**（2026-10-23 用户定名） | 不打开编辑界面：开始页「说一句话」的输入框、聊天页、右侧拓展栏、详细编辑。在线浏览器登录后的默认界面，顶栏工作方式开关的第一格。开始页上**点「最近项目」那一排的缩略图卡片直接进传统式**，点侧栏的项目条目才进这个项目的聊天页（2026-10-23 用户定）。侧栏里展开和打开是两回事（2026-10-26 用户定，issue #15）：点项目行首的小三角只展开它、列出这个项目里的 Agent 对话，不切换当前项目，可以同时展开多个项目；点项目名才是打开它，当前项目仍然只有一个。没打开的那些项目底下列出来的对话只能点进去（点了就是打开那个项目并进这条对话），改名、置顶、归档、删除要先打开那个项目 | 主要是 Agent 动手；用户也能自己调——从右侧拓展栏的「画面」进详细编辑，那里的时间轴可调。要整套编辑界面才切传统式 |
| **传统式** | 打开编辑界面 | 用户和 AI 栏里的 Agent |
| **SKILL** | 默认关闭编辑界面，软件转入后台运行。只在桌面应用中提供 | 桌面 APP 里的 Agent；用户可随时打开界面一起改 |

**氛围式里输入框在哪（2026-10-26 用户定）**：平时在聊天列底部。从右侧拓展栏的「画面」进「详细编辑」后，时间轴编辑区占满整个聊天区，输入框搬进右侧拓展栏里新建出来的那块聊天面板；那块面板放不下长对话，只有最新一条 Agent 回复留全文，其余回复和用户的话都收成两行，点一下才展开。用户自己收起右侧拓展栏时，详细编辑继续开着，输入框掉回聊天列底部——两个开关各管各的。

**后台运行（只在桌面应用中提供）**：关闭编辑界面不退出软件，软件转为托盘图标和悬浮窗继续运行；点击托盘图标或悬浮窗重新打开编辑界面；在托盘图标或悬浮窗上右键选择关闭，或选择编辑界面菜单「文件 → 退出」，软件才退出（2026-10-02 用户决定保留该菜单项）。浏览器中关闭页面即结束本次编辑。

## 主线

| 步 | 做什么 | 主体 | 分册 |
|---|---|---|---|
| 0. 开始 | 新建或打开项目，本机项目或多人共用的共享项目 | 用户 | `workflow/project.md` |
| 1. 前期准备 | 把素材放进项目，并让系统理解素材 | 用户和 Agent | `workflow/materials.md` |
| 2. 核心制作 | 用户发送指令，Agent 执行 | 用户、Agent | `workflow/production.md` |
| 3. 用户实时查看 | 用户看画面，看 Agent 的进度 | 用户 | `workflow/editing.md` |
| 4. 用户交互修正 | 用户再发一条指令，或自己动手改 | 用户 | `workflow/editing.md` |
| 5. 交付 | 导出成片，保存项目 | 用户 | `workflow/project.md` |

第 2 到 4 步是循环，直到用户满意再交付。

## 人机协作规则

### Agent 接入方式

| 类别 | 是什么 | 在哪对话 | 对应的工作方式 |
|---|---|---|---|
| **CLI** | 本机的命令行 Agent | AI 栏 | 传统式 |
| **API** | 直连模型接口 | AI 栏 | 传统式 |
| **桌面 APP** | 本机的桌面 Agent 应用 | 桌面 APP 自己的窗口 | SKILL |
| **云端** | 托管方的云端 Agent | AI 栏 | 传统式 |

在线浏览器模式只有「云端」一种接入。桌面版在项目放云端时多出「云端」一项，缺省仍是本机的接入方式。云端的对话发出后可以关掉软件，它在云端继续；重新打开项目能接着看、停掉或接着说。〔裁：主会话 2026-10-06，待用户合入前审〕

桌面 APP 的 Agent：

- 通过 MCP 接入本软件，权限与 AI 栏里的 Agent 相同。
- 桌面 APP 的每个会话是一个独立的 Agent。打开编辑界面时，每个会话在 AI 栏里单独显示，标明所属厂商和正在进行的操作。
- 用户手动修改时，它和 AI 栏里的 Agent 一样收到通知。

### 创造力等级

项目有一个默认等级，在项目设置里选，出厂为「高」。AI 栏里的每个对话默认取项目的等级，可以单独改。桌面 APP 的会话跟随项目的等级。等级决定该对话的 Agent 能改到多深，同时约束卡片、效果和测量：

| 等级 | 允许 |
|---|---|
| **低** | 只用已有的卡片和效果，只改参数；测量只用内置方法 |
| **中** | 在已有卡片和效果的基础上，可以改它们的代码或表达式，但不新建 |
| **高** | 可以新建任意卡片和效果，可以写自定义测量代码 |

### 多 Agent

- 用户可以同时开多个 Agent，每个 Agent 一个对话。AI 栏里的 Agent 标签按项目分开，每个项目一份；一个会话都没有时显示开始页（2026-10-22 用户定，见 `workflow/editing.md`「AI 栏的 Agent 标签」）。
- 一个主 Agent 可以拉起其它 Agent 并给它们分派任务，拉起时可以给它们附加预设的角色。
- 各 Agent 声明各自的改动范围，互发消息协调。

### 保护

- 破坏性操作有门槛：删除片段、序列、效果时要说明理由，理由对用户可见。
- Agent 之间不悄悄互相覆盖：一个 Agent 改到别的 Agent 正在改或刚改过的内容时，双方都要知道。
- 用户正在编辑的内容要让 Agent 知道：Agent 看或改用户正在编辑的内容时，系统在返回里直接标出「用户正在编辑」，避免它覆盖用户的编辑。这是提示，不是禁止，因为用户可能正是在这个位置给 Agent 下指令。
- Agent 需要用户做事或回答时，停下并说明，不继续改。
- Agent 不能绕过工具直接改项目。

### 进度可见

- 对话气泡里显示 Agent 说的在做什么（它用 send_message 对用户说的话；没说时是它的文字回复）。进度条目（做了、待办、问题）和操作详细预览在气泡下方的「Agent 操作」里按轮显示（2026-10-20 用户定，原话「把Agent操作记录哪里换成气泡里面那个可视化组件。气泡里面只展示在做什么（harness可能要改，比如加入send_message(user,xxx)的用法。）。」；取代原来的「Agent 的文字回复不显示给用户。用户看到的是 Agent 交上来的进度条目（做了、待办、问题）和操作详细预览。」）。
- 桌面 APP 的 Agent 的文字输出本软件拿不到。它按 SKILL 提示词约定的结构化方法汇报进度，显示方式与 AI 栏里 Agent 的进度条目相同。
